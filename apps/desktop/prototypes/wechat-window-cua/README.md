# 微信小窗口原型

macOS 支持将已登录的微信原生窗口贴合到微信数域左侧，并跟随数域窗口移动和调整尺寸。微信仍是独立的系统窗口，因此切换焦点、窗口遮挡和跨桌面表现与 Windows 的原生子窗口不同。关闭数域时会尝试恢复微信原来的位置和尺寸。

首次使用需要在“系统设置 → 隐私与安全性 → 辅助功能”中允许窗口控制程序；如果微信没有打开或未显示聊天窗口，请先打开微信，然后在数域中点击“重新连接”。开发和构建时通过 `scripts/build-wechat-windowctl.mjs` 编译原生控制程序，需要安装 Xcode Command Line Tools。

macOS 在微信数域首次启动、窗口捕获准备好后，会自动检查一次当前未读会话。随后同时使用两种触发信号：通过辅助功能事件监听系统通知中心显示的微信横幅；以及通过 ScreenCaptureKit 接收窗口画面（最多每 3 秒一帧），在本地检测会话列表区域的红色未读标记。监听和分析截图共用同一条捕获流，操作后会等待新画面或明确的未变化状态，避免反复创建截图流。系统通知到达后会截图交给 hy3 检查可见的未读会话；本地红点发生变化后会检查红点对应的会话。之后只有这些事件才启动模型调用，系统通知横幅与窗口变化共用分析队列并尽量去重。窗口流第一帧用作基线。

触发后模型逐步观察微信截图并选择导航、点击或滚动，例如当前在朋友圈时先回到“消息”，再寻找未读会话。寻找会话时只发送左侧导航栏与列表的局部截图；进入会话后只发送聊天区域的局部截图。裁剪基于当前微信布局和窗口尺寸，界面改版或手动调整布局后需要重新验证边界。模型根据画面决定如何向上滚动和收集约 5 页上下文，再识别、汇总并提出建议回复。确认仍为目标会话、输入框可见且为空时，程序尝试将建议填入微信输入框；不会发送或模拟回车。无法确认时建议保留在右侧，已有草稿不会被主动覆盖。

填入建议后，新触发暂时排队，以免在用户发送前切换会话。窗口帧检测到同一会话的输入框从有内容恢复到空白时自动继续；若未能可靠观察到这一变化，可以点击“已处理草稿，继续分析”。本地视觉检查依赖微信布局，无法保证识别所有输入框状态，发送前应由用户确认输入内容。

代码限制操作范围、检查窗口焦点并在界面变化时停止当前操作，保留排队的触发并继续监听；窗口捕获断开后持续退避重连。模型选定聊天滚动位置后，先在本地收集最多 6 张重叠截图，再最多并发 4 个识别请求，按截图顺序拼接。每张已识别的文字立即保存在 Electron userData 下的 `wechat-history` 目录（目录权限 0700，文件权限 0600），截图本身不持久化；后续同名会话分析会读取最近的部分记录作为上下文。当前仅能使用可见会话名称作为暂定身份，同名联系人可能混淆，不能作为可靠的联系人唯一标识；识别错误和重叠页面也会保留，汇总时仅对能确认的重叠去重。历史保存在本机明文文件中，操作系统账户备份可能包含这些内容。

同一次请求中同一截图最多交给识图工具一次，遇到重复识图或无效判断会停止并记录，不对同一触发自动重试。截图会发送给配置的 hy3 模型；首次运行可能需要在“系统设置 → 隐私与安全性 → 屏幕与系统音频录制”中授权。系统通知中心的无障碍结构可能随 macOS 版本变化；没有显示横幅、通知内容隐藏或同样通知被系统合并时，通知信号可能缺失，需要依靠窗口检测。监听和模型服务异常期间仍可能遗漏消息，恢复监听后会补做一次未读检查。

自动点击和滚动时微信需要位于前台且目标区域未被遮挡。窗口最小化时监听和分析暂停，恢复后重新建立基线。检测依赖微信界面布局与颜色，滚动、切换界面或微信升级可能产生误报或漏报；如果无法确认目标会话、列表在识别期间变化或微信失去焦点，分析会停止并在侧栏显示原因。点击会将对应微信会话标记为已读。

以下消息分析和后台操作说明适用于 Windows：

运行完整验证窗口：

```powershell
node ./run.cjs
```

在 launcher 的“选择数域”中点击“微信”即可打开独立的“微信数域”系统窗口，也可以把微信拖进 Dock 固定。启动后的 Dock 灰点表示数域仍在运行；点击图标可在置前与送到后台之间切换，右键“关闭数域”会关闭系统窗口并还原微信原生窗口。启动时先枚举已有微信窗口，跳过登录入口，优先复用聊天窗口；只有系统中没有任何微信进程时才启动微信。若聊天窗口被托盘隐藏且无法定位，请从 Windows 托盘打开原聊天窗口，然后点击“重新连接”。窗口大小按微信当前实际尺寸计算，微信通过 Windows `SetParent` 嵌入这个系统窗口，并随其拖动。打开时不截图、滚动或调用模型；点击“分析”后右侧显示 CodeBuddy `hy3` 的结果。也可单独运行 `node ./run.cjs`。

点击右上角“分析”后，原型才开始截图和操作：返回会话列表、定向后台滚轮滚到顶部，让 hy3 从截图识别第一个头像带红色未读标记的会话，再定向后台点击进入。之后在聊天区域连续向上滚动几屏并截取重叠画面；如果连续两次确认聊天区没有变化，就提前停止滚动，不把重复截图发给模型。hy3 去重、提取最近 10 条完整可读消息并汇总到右侧。若图片或文字不清晰，会明确说明不足 10 条或无法确认。不会发送消息。

正常关闭数域时会还原微信原来的父窗口、窗口样式和位置。

本机微信的 UI Automation 当前只暴露两个通用 Pane，未暴露消息文本或列表控件。后台操作使用 `background-input.ps1` 对微信窗口定向投递鼠标消息，截图使用 `PrintWindow`。这套坐标与窗口结构绑定，微信升级后需要重新验证。

底层脚本也可单独调用。`prepare` 在微信未运行时尝试从常见安装路径启动它，并保留用户当前窗口尺寸。截图坐标以**整个窗口左上角**为原点。

```powershell
pwsh ./wechat-window.ps1 prepare
pwsh ./wechat-window.ps1 capture -Output ./capture.png
pwsh ./wechat-window.ps1 click -X 120 -Y 80
pwsh ./wechat-window.ps1 scroll -X 300 -Y 250 -Delta -3
```

每次操作都重新定位微信主窗口、拉到前台并核对前台句柄；坐标越界会拒绝执行。截图使用 `PrintWindow` 按微信窗口句柄捕获，避免混入遮挡窗口。底层 `click` 仅作单击，`scroll` 为滚轮。

验证顺序：先运行 `status`，再运行 `prepare` 和 `capture`，根据截图确认窗口边界后才执行点击或滚动。微信关闭或未登录时，脚本会直接报错。
